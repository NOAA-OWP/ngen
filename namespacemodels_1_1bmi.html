Get a pointer to a model variable's own storage, addressed as.

Template Parameters
T.

The sibling of GetValue() for callers that want the model's memory rather than a copy of it. Bmi_Adapter exposes the pointer untyped, because BMI has no way to describe what is behind it; every caller therefore has to supply the type, and nothing in BMI obliges that type to be the width the model allocated. Indexing with the wrong stride walks off the variable, so the item size is checked here rather than at each call site.

An adapter whose language cannot hand out pointers says so from GetValuePtr() itself; this does not need to know which those are.

void models::bmi::require_item_size ( const std::string & type,
size_t item_size,
const std::string & described )
inline

Throw unless type names a C++ type of exactly item_size bytes.

A model reports a variable's type name and the size of one item separately, and nothing in BMI makes the two agree. Every buffer here is sized from one and addressed as the other, so a disagreement reads or writes past the end – on a read, out of the buffer; on a write, out of it by whatever the model takes. Neither is detectable afterwards, so refuse up front.

◆ with_bmi_type()

template<typename F >
auto models::bmi::with_bmi_type ( const std::string & type,
F && f )

Call f with the C++ type that a BMI type name denotes.

BMI reports a variable's type as a string, and every operation on that variable has to pick the matching C++ type before it can do anything. This is the one place that mapping lives: f is a callable with a template parameter, invoked as f.template operator()<T>(), and this picks the T.

Several spellings may denote one type – "real" and "float", "integer" and "int" – and the table resolves them alike. Which spelling a given model reports is not this function's concern.

// "Give me this value as whatever the variable declares." The target type is a string, so the
// cast cannot be written directly: capture the value, and let the table supply the type.
std::shared_ptr<void> as_declared_type(const std::string &type, double value)
{
return with_bmi_type(type, [&]<typename T>() -> std::shared_ptr<void> {
return std::make_shared<T>(static_cast<T>(value));
});
}

Definition bmi_utilities.hpp:85

Two things there are easy to get wrong.

The lambda takes no arguments. value arrives by capture, which leaves the parameter list free for the one thing this function supplies – f.template operator()<T>() passes a type and nothing else. That is what lets one table serve callers whose data is a scalar, an iterator pair, or a pointer and a count: each seals its own data into the closure.

The -> std::shared_ptr<void> is load-bearing. make_shared<T> yields a shared_ptr<T>, a different type in every branch, and the branches have to agree on one return type. Converting there is the only place T is still known. Omitting it is a compile error rather than a silent conversion – as is a body that does not compile for every type below, even one no caller ever asks for, since all of them are instantiated.
