◆ primitive_type

enum class models::bmi::primitive_type : std::uint8_t
strong

The type of one item of a BMI variable, independent of how any language spells it.

BMI reports a variable's type as a name in the model's language, and some names – Fortran's "real", Python's "int" – need the item size to settle which type they mean. The name is resolved to one of these once, and the framework passes this around thereafter rather than the name.

The fixed-width enumerators mean exactly that width and representation. Two do not:

  • long_double is the platform's C++ long double, whatever that is: IEEE binary128 on aarch64 Linux, x87 80-bit extended precision padded to 12 or 16 bytes on x86, or the same as double on others. It is what a model means by naming "long double".
  • f128 is IEEE binary128, whatever C++ type holds it. It is supported only where long double is binary128; see with_primitive_type() for the path elsewhere.

Get a pointer to a model variable's own storage, addressed as.

Template Parameters
T.

The sibling of GetValue() for callers that want the model's memory rather than a copy of it. Bmi_Adapter exposes the pointer untyped, because BMI has no way to describe what is behind it; every caller therefore has to supply the type, and nothing in BMI obliges that type to be the width the model allocated. Indexing with the wrong stride walks off the variable, so the item size is checked here rather than at each call site.

An adapter whose language cannot hand out pointers says so from GetValuePtr() itself; this does not need to know which those are.

primitive_type models::bmi::parse_bmi_type ( std::string_view type)

The primitive_type a BMI type name denotes.

This is the one table of type spellings. Several may denote one type – "real" and "float", "integer" and "int" – and C spellings resolve to the width they have on this platform. A name whose width depends on more than the name, as Fortran's "real" under -fdefault-real-8 does, is for an adapter's Bmi_Adapter::get_primitive_type() to settle first.

◆ with_primitive_type()

template<typename F >
auto models::bmi::with_primitive_type ( primitive_type type,
F && f )

Call f with the C++ type that type denotes.

Every operation on a variable has to pick the matching C++ type before it can do anything, and this is where that happens: f is a callable with a template parameter, invoked as f.template operator()<T>(), and this picks the T.

// "Give me this value as whatever the variable declares." The target type is only known at run
// time, so the cast cannot be written directly: capture the value, and let this supply the type.
std::shared_ptr<void> as_declared_type(primitive_type type, double value)
{
return with_primitive_type(type, [&]<typename T>() -> std::shared_ptr<void> {
return std::make_shared<T>(static_cast<T>(value));
});
}

Two things there are easy to get wrong.

The lambda takes no arguments. value arrives by capture, which leaves the parameter list free for the one thing this function supplies – f.template operator()<T>() passes a type and nothing else. That is what lets one dispatch serve callers whose data is a scalar, an iterator pair, or a pointer and a count: each seals its own data into the closure.

The -> std::shared_ptr<void> is load-bearing. make_shared<T> yields a shared_ptr<T>, a different type in every branch, and the branches have to agree on one return type. Converting there is the only place T is still known. Omitting it is a compile error rather than a silent conversion – as is a body that does not compile for every type below, even one no caller ever asks for, since all of them are instantiated.
