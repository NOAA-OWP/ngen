18// Catchment output manager, modeled on NexusOutputsMgr: a concrete backend is constructed with the
19// full set of catchments/fields it will handle (see FeatureDescriptor and the backend's
20// constructor), then data is pushed in via receive_data_entry and the backend serializes it however
21// it chooses. Constructing with the complete set means a backend has everything it needs to lay out
22// its sink up front, rather than discovering features incrementally. The two hierarchies
23// (nexus/catchment) are kept separate for now and can be unified behind a shared base later.
